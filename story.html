The Story of DOOM

How four programmers in Texas built a game that will not die.

Before DOOM

id Software started as four guys working for a company called Softdisk in Louisiana. John Carmack, John Romero, Tom Hall and Adrian Carmack spent their nights making games nobody had asked them for. In 1990 Carmack worked out how to get a PC to scroll smoothly, which most people at the time thought only a console could do. The group used it to rebuild the first level of Super Mario Bros. 3 in a single night and mailed the demo to Nintendo. Nintendo passed, but the team knew what they had. They left and started id Software in February 1991.

Commander Keen paid the bills for the next year or so. Then Wolfenstein 3D came out in May 1992 and changed things. It put you inside a maze of textured walls at a speed nobody expected from a 386. It sold well and got a lot of attention, some of it bad. id started on something bigger almost right away.

Building the Engine

Carmack wrote most of the DOOM engine over 1992 and 1993. Wolfenstein levels were a flat grid of square rooms. DOOM levels could have angled walls, rooms at different heights, staircases, moving platforms and pits of toxic waste. He got there using binary space partitioning, a method out of computer graphics research that no shipped game had used yet. The BSP tree tells the engine what order to draw things in, so it never has to check every surface. That is the main reason the game ran well on hardware with no business drawing 3D.

A lot of the rest is smoke and mirrors. Lighting is faked by swapping in darker copies of the palette, so far hallways fade out and the level feels bigger than it is. Enemies are flat images drawn from eight angles, which is why a cacodemon always looks like it is staring right at you. None of it is real 3D. Every shortcut was there so the game would still run on a 386 with 4 MB of RAM.

Release and Shareware

DOOM went up on a university FTP server in Wisconsin on December 10, 1993. So many people tried to grab it at once that the server fell over and the admin had to ask id to hold off. The first nine levels were free to copy and pass around, and the rest cost money. Within two years people were claiming it was installed on more PCs than Windows was.

Deathmatch shipped with it. Office networks that had been put in for spreadsheets got buried under DOOM traffic, and plenty of companies banned it outright. The word deathmatch came out of id's office, and the multiplayer culture it started is still going.

The Source Code Release

On December 23, 1997, Carmack released the DOOM source code. That is the reason this site exists. Within a few weeks it was running on Linux, on the Amiga and on the Sega Saturn. Source ports like Chocolate DOOM, PrBoom and GZDoom kept it playable on hardware id never planned for, and each one gave the next person a head start.

The code is small, it is written in portable C, and it barely needs any memory. That combination turned it into the standard test for whether something counts as a real computer. If a device has a processor, some memory and any way to light up pixels, somebody is going to make it run DOOM and then post the video.

Why It Never Stopped

Getting DOOM onto a printer or a thermostat is not really about the game. You have to read documentation that was never written for you, find some way to load your own code onto the thing, and fit a renderer into hardware built to show four lines of text. The payoff is a short video, but the real point is showing the hardware can do more than the company that sold it wanted.

Thirty years later DOOM is a benchmark, a running joke and a rite of passage all at once. My favorite ports are over on the Devices page.
